# agent-autosuggest v0.2.0

**Released 2026-10-25. A minor release.** Four changes since [v0.1.0](v0.1.0.md): a churn solution
whose feature plans are ready is suggested instead of declined (prompt **v5**), and the three fixes
from the 2026-10-21 security review. Image: `docker.io/oramasearch/agent-autosuggest:v0.2.0`.

This release is the tree of `dev` at `9b45383` (the merge of #18) with these notes and the version.

## What it includes

Every pull request merged into `dev` since v0.1.0 (`git log --first-parent v0.1.0..origin/dev`):

### Ready data is suggested, and a real transform names its Lake capability (prompt `v5`) — #24

*Scan my workspace* suggested nothing on lake-dev: it declined every churn table and asked for an
"approved snapshot/as_of setup" Lake has no way to make.

- `solutions.enforce`: a runnable solution the model declines as "transform first" is suggested
  instead when every methodology at the chosen level plans `ready` on one dataset
  (`methodologies.ready_dataset`). The model's preparation becomes a `required_first` step, and the
  grounding names the dataset and the cutoff Lake inferred (`inferred.as_of`).
- `methodologies` reads zetta's real `transform_required` shape and Lake's `performed_by`. A real
  transform is declined as `transform first: <name>: <description>. Lake does it with <capability>`.
  Without `performed_by` the agent falls back to the same mapping.
- `validate`: a "transform first" that names no Lake capability (`plan_features`, `upload_dataset`,
  `workspace_sql`, `create_dataset_from_query`, `generate_dataset`) is a defect, handed back in the
  repair round.
- Prompt `v5` (`PROMPT_VERSION = "v5"`): a ready composition is suggested with its preparation in
  `required_first`; the `time` role is met by a snapshot column or a declared `as_of`; "approved
  snapshot" requests are forbidden. `v4` is kept in `prompts/`.

It pairs with lake#1189 (`plan_features` from a
dataset alone, with its snapshot cutoff, and `performed_by`). Against a Lake without it, a table with
a date column still plans `transform_required`; the agent then declines it naming
`plan_features`/`upload_dataset`, but suggests nothing for it.

### The service token is compared in constant time and always required — #20

`turn_refusal()` checks the bearer with `hmac.compare_digest` over bytes. With
`AGENT_SERVICE_TOKEN` unset or empty, `POST /v1/turn` answers `503` to every turn (in v0.1.0 the
route was open). A wrong or missing bearer is `401`, as before. Turns from Lake's agent bus are
unaffected.

### A turn's credential goes only to the service's own `LAKE_URL` — #22

In v0.1.0 a turn's `lake_url` and `zetta_base_url` chose where the turn's bearer was sent.

- The model gateway and Lake's capabilities (`workspace_query`, `list_apps`, ...) are always reached
  at `LAKE_URL`. A turn's `lake_url` is ignored.
- `zetta_base_url` (*Scan my workspace*) is accepted only on `LAKE_URL`'s origin and under its path,
  with no user info, query, fragment, backslash or dot segments. Anything else refuses the turn.
- With `LAKE_URL` unset, or not an absolute http(s) URL, every turn that would send a credential is
  refused before any request.

### No turn trace on the pod's disk — #18

A turn no longer writes `<TRACE_DIR>/<trace_id>.json`, and the service no longer reads `TRACE_DIR`;
the `Dockerfile` drops its default. The answer still carries `trace_id`, and Lake keeps the whole
answer in the task's sealed record in the turn's workspace Zetta.

## Before it rolls: the settings it needs

| Setting | Needed by | Rendered by the operator |
|---|---|---|
| `AGENT_SERVICE_TOKEN` | #20: without it every direct turn is refused (`503`) | Yes, on every library agent |
| `LAKE_URL` | #22: without it (or not absolute http(s)) every turn that sends a credential is refused | Yes (Lake's internal URL) |
| `AUTOSUGGEST_MODEL` | Unchanged; the model name | Yes (with `AGENT_MODEL`, both set to the Lake's agent model) |
| `TRACE_DIR` | No longer read | Still set to `/tmp/traces`; ignored |

Nothing new is needed from the operator. For the best answers on date-bearing tables, Lake should
carry lake#1189 (merged into lake `dev`).

## What it does not include

Unchanged from [v0.1.0](v0.1.0.md#what-it-does-not-include), except that traces are no longer kept
at all:

- **A trained model.** Every turn is a frontier model with few-shot retrieval.
- **A large precedent set.** The `corpus` context at `a882954` holds one worked example.
- **Any write.** App actions are proposals for a person to confirm; ApplicationAgent performs them.
- **Turn kinds.** The task `kind` is ignored.
- **Workspace identity.** Turns carry `customer_id`; the task's `workspace_id` is not forwarded.
- **Lease renewal** for long turns beyond activity, and back-off on empty bus reads.
- **Bus back-pressure**: tasks are claimed before a worker is free.
- **Workspace context from the command line.**

## Known issues

Security-relevant first. All open at this tag.

1. **The bus claims tasks before a worker is free**
   (#23, medium, denial of
   service): `lake_bus.work` claims every received task into the executor's unbounded queue, so one
   tenant's burst holds task credentials in the process and delays other tenants while their leases
   run. The fix is the port of agent-ask-orama#47.
2. **Library agents hold live task credentials for every tenant they serve**: one shared pod runs every tenant's
   turns with their task credentials.
3. **The workspace is not passed explicitly**: the agent sends only
   `customer_id` on its reads, never the task's `workspace_id`.
4. **The lease is kept by activity only.** Lake renews a claim's lease on every capability call made
   with the task credential, so a turn is reclaimed only if one step, such as one model call, outlasts
   `lease_seconds` (600 by default). Not observed.
5. **The command line validates without workspace evidence**.
6. **Corpus drafts fail validation**:
   the corpus's examples do not choose a registry level for S-1. The image keeps the `a882954` corpus.

Closed since v0.1.0: #13,
#19,
#21, and
lake#795 (a discover turn failing on `list_apps`).
